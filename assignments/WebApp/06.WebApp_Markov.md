# Web App #6 - Markov Music Generator
*Create one or more Markov graphs to guide a sequence generator*

In this programming exercise, we will define a "graph" for a "Markov chain" that will generate a single-line melody according to probabilities defined by the composer (that's you). This is an algorithm found in many applications in which computers make decisions based on probability or observed patterns. The algorithm itself pre-dates modern computers. It is based on a kind of controlled randomness ("Stochastic" process) that chooses the next state based on a list of possibilities tied to the current state.

The machine won't do any learning or adapting. Instead, you will construct, by hand, a probability table that will govern the behavior of your system. It's a form of composition in which you set the parameters and let the process determine the actual result. The player application will play a semi-random note sequence using your data table (downloadable as "markov.json") to choose the notes and rhythms. 

## Step 1 - Build a graph and export the .json data file
Let's build a musical Markov chain graph for music generation! It will have two main components: a **pitchSet** graph and a **rhythmSet** graph.

1. Go to <a href="https://editor.p5js.org/dbwetzel/full/rL0qmZFOC" target="_blank">https://editor.p5js.org/dbwetzel/full/rL0qmZFOC</a> to see the newest user interface (beta v. 0.4)
 - The page should open with a starter graph containing one pitch "node" and one rhythm "node"
 - By default, the opening State is set to "C4" and the first Node is also "C4" with an empty transition list. 
 - If you press play (green play button), you should hear a steady repeating C4 in constant quarter notes ("4n").
 - If you scroll down to see the JSON data, it looks like this: 
  ```javascript
  [
    {
      "name" : "Untitled",
      "pitchSet" : {
            "state" : "C4",
            "matrix" : {
                  "C4" : [ ]
            }
        },
      "rhythmSet" : {
              "state" : "4n",
              "matrix" : {
                    "4n" : [ ]
              }     
        }
  ]
  ```

2. Change the name of the graph (call it whatever you like - you can rename it later also). 
 - Click **"Change Name,"** type a new name in the box, and hit "return/enter."
3. D**efine the pitchSet.** This is the list of pitches that your music generator can play.
 - There is one pitch node already provided ("C4").
 - Add new pitch nodes by selecting a **note name** and an **octave** designation from the menu; then **press the "+" button**
 - You can keep it simple with two or three pitches, or get really complex. Larger pitch sets will get crowded in this interface (sorry!)
 - You can choose notes within a specific scale or chord or you can add notes freely.
 - Keep in mind that I have given "enharmonic" equivalents for most pitches so that you can define keys and chord structures however you like. The pitches "C#4" and "Db4" will sound the same (MIDI note 61) but might be treated very differently in your graph. 
 - You can **delete a pitch node** by selecting a pitch/octave combo and **pressing "-"**; if there are no other pitch nodes, the default "C4" will regenerate. Can't have a graph with no pitch nodes!
4. Choose a starting pitch **"State"**
 - Look for the dropdown menu of current pitch nodes under **"Set initial state ..."** (right side, top)
 - Pick the pitch from your list that you want to start from (the menu updates with each added/deleted node)
5. Add **pitch transitions** to your graph to make it more complex and play beyond the starting pitch node.
 - **Shift-click on a node** to highlight it for connections to other nodes
 - While a node is highlighted, **hold the 'a' key** and click on another node to add a connection between the first node and the second.
 - You can connect a node to **itself** (created repetitions!)
 - Multiple occurrences of a transition make that transition **more likely**
 - Try to **keep track** of the transitions and make sure that each node can be reached as a transition from another note and that the transitions for each node lead to at least one other node. The graphical player interface will show arrows for each transition between different nodes.
 - Conversely, while a node is highlighted (shift-clicked), **hold the 'd' key to delete a connection.**
 - The list of possible transitions for the highlighted node should appear on screen while editing
 - **Click anywhere outside the nodes** when you are done editing transitions
6. **Define the Rhythm Set.** Rhythms are defined as a separate matrix from pitch. Like the pitchSet, we have a starting state (the first note will have this value). Instead of a note value, we need a rhythmic duration value (in Tone.js notation: "4n", "8n", "2n", etc.)
 - Click the **"Show Rhythm"** button (next to the play button, center left)
 - **Add rhythm nodes** to make your player more rhythmically complex. Choose a rhythmic duration value from the dropdown list ("Add/delete nodes ... ", top center) and press "+" to add that value to the list of rhythm nodes.
 - Press "-" to **delete** the node currently selected in the dropdown list. If it's not included in the graph this will have no effect.
 - Change the opening rhythm "state" (if desired)
 - **Connect the nodes with transitions** in the same way as outlined above for pitch transitions. Arrows will indicate existing transition possibilities (the darker the line, the more likely the transition).
 - Shift-click a node to edit its transition list; Hold 'a' or 'd' and click on another node to add or delete a connection.
7. **Test your player.** You should see a colored circle (colors are random) with the name of each node in your matrices/graphs. 
 - You should also see arrows indicating the possible connections from one note to the next. 
 - **Press the play button** to start your music generator. You should see and hear a Markov-generated note sequence. 
8. Make a second graph (**"Create New Graph"** button). 
 - Follow the steps above to make it interesting. 
 - Both graphs should have more complexity beyond the starter template.
